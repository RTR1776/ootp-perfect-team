## Top 10 — biggest improvement for the effort

1. **Make it work on a phone.**
   - The sidebar is a fixed `w-60` and the content has a fixed `pl-60` at every width (`src/app/layout.tsx:40-41`). On a 390px phone, about 150px is left for content.
   - Fix: below `lg`, hide the sidebar and add a drawer or hamburger in `header.tsx`, or a bottom tab bar (Build / PTCS / Cards / Upload). Change `pl-60` to `lg:pl-60`.

2. **Add loading, error and not-found screens.**
   - There is no `loading.tsx`, `error.tsx` or `not-found.tsx` anywhere. Every page is `force-dynamic` and does heavy DB work.
   - When you switch events in the Build picker, the old page just freezes with no feedback. A DB hiccup shows Next's raw error screen.
   - Fix: add skeleton tables, a themed error card with Retry, and a pending state on the tournament picker (`useTransition`).

3. **Build a real home page.** `/` redirects straight to `/build`, which opens on a bare native `<select>`. A home dashboard would make the site feel like a product:
   - data freshness (reuse the sources table from `/upload`)
   - PTCS pace against the cutoff line
   - today's and this week's events, each linking straight into Build
   - saved rosters, and market movers on cards you own

4. **Give it a visual identity.**
   - The favicon is the stock create-next-app icon. `public/app-icon.png` exists but nothing uses it. `public/{next,vercel,file,globe,window}.svg` are leftover boilerplate.
   - The only brand mark is a green "PT" square (`sidebar.tsx:36`).
   - Ideas:
     - a condensed sports display face for titles and big numbers (Oswald or Barlow Condensed) alongside Geist
     - a scoreboard or stitching accent
     - card art as thumbnails in `/cards` results and in roster slots (today it appears only in the hover peek)

5. **Make tier colors and status colors readable in both themes.**
   - Tier badges use the raw tier hex as text color (`tier-badge.tsx:20-24`). Gold and Silver on white are about 1.5:1 contrast, which is unreadable in light mode.
   - The tier palette is defined twice (`globals.css` and `lib/tiers.ts`), and "Perfect" exists only in the JS copy.
   - Status colors are dark-only shades such as `text-emerald-400` and `text-amber-400` (`cards/page.tsx`, `ptcs/page.tsx`, `meta/page.tsx`, `market/page.tsx`).
   - Fix: add `--tier-*`, `--positive`, `--negative` and `--warning` tokens with light and dark values, and use them everywhere.

6. **Move the optimizer off the main thread.**
   - Optimise runs on the UI thread and, by the code's own measurement, freezes the tab for 14–17 seconds (`roster-builder.tsx:703-735`).
   - Fix: run it in a Web Worker, with a progress readout ("+X runs, pass 3/…") and a Cancel button. The inputs are plain data, so this is straightforward.

7. **Add a safety net: a `test` script and CI.**
   - The 48 tests exist but `package.json` has no `test` script. The RUNBOOK's `src/lib/**/*.test.ts` glob does not recurse in a default shell.
   - There is no `.github/` folder, so nothing runs on push. That is how the park-sweep break got in.
   - Fix:
     - Add `"test": "node --import tsx --test $(find src -name '*.test.ts')"`.
     - Add a small GitHub Actions workflow that runs `tsc`, the tests and `next build`.
     - Exclude `scripts/` from the app tsconfig (give it its own tsconfig) so a one-off script cannot fail a deploy.

8. **Close the login gaps.** The site is on the public web behind one password.
   - Nothing limits guesses on `/api/login`. Add a per-IP rate limit, or at least a delay on failure.
   - `login/page.tsx:24` redirects to `?next=` without checking it, which is an open redirect. Accept only paths that start with `/` and not `//`.
   - `auth.ts:34` leaks the password length through an early return. HMAC both values and use `timingSafeEqual`.

9. **Let a failed upload be retried.**
   - `api/upload/route.ts` writes the `uploads` row, including the file's sha256, before the child rows. If a chunk fails, re-uploading the same file hits the dedupe check (`:132-137`) and reports "already imported", so the data never lands.
   - Fix: record the sha only on success, or make the write atomic with Neon `batch()` or a Pool transaction.
   - Also: dump uploads skip the import-batch lineage record, and every roster save inserts a new row. Saved rosters have no update, delete or rename.

10. **Split `roster-builder.tsx` (1,413 lines) and share one table component.**
    - Tables behave differently on every page: some sort both ways, some one way, some not at all. Only one table has a sticky header, and number alignment varies.
    - Fix: build one `ui/data-table.tsx` with two-way sort and `aria-sort`, a sticky header, right-aligned `tabular-nums` numbers and a pinned first column on narrow screens.
    - Then split Build into Picker, Pool table (virtualized; today it renders up to 400 rows and does a `slotOrder.some` per row), Roster board, Card peek and Validation.

## Performance

- **`/build` recomputes everything on every request.**
  - It selects the whole `cards` table (about 3,700 rows, each with a ratings JSONB) and re-scores it with `envFitMaps`.
  - About 12 queries run one after another; several are independent and could use `Promise.all`.
  - Fix: cache the scored universe per (tournament, latest shop upload).
  - `/market`, `/meta` and `/played` do similar full scans.
- **Build page props.** `build/page.tsx:311` sends `variantRatings` to the client untrimmed while `ratings` is trimmed.
- **Unused dependencies.** `zustand`, `recharts`, `@tanstack/react-table` and `@tanstack/react-virtual` are never imported. Use them (react-virtual and react-table fit item 10) or remove them.

- **Lint.** `pnpm lint` reports 231 errors. 215 are in `scripts/`; the 16 in `src/` are mostly `react-hooks/static-components`, where components are defined inside `roster-builder.tsx`.
  - Scope lint to `src/` or relax it for `scripts/`, then fix the `src/` ones so lint can gate CI.
- **Two write paths per upload kind.** The API route and the CLI importers (`import-collection`, `import-league`, `import-current-cards`) each have their own insert and dedupe code. Share one `lib/ingest/*-writer.ts` per kind.
- **Two `parseCsv` implementations:** `lib/ingest/csv.ts` and `lib/ingest/eligible-pool.ts`.
- **Dead files:**
  - `src/data/curves.v1-projections.json`
  - `scripts/.diag.ts`
  - the starter SVGs in `public/`
  - the boilerplate `web/README.md`
- **A literal NUL byte in `scripts/import-observed.ts:135`** makes git treat the file as binary, so its diffs don't show. Use `"\u0000"`.
- **Database TLS.** `db/client.ts:68` sets `rejectUnauthorized: false` for non-Neon hosted Postgres.
